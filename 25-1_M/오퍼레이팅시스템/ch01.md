# 1. Computer System Overview I
"OS의 또 다른 이름: **자원 관리자**"
> 대략적인 흐름: HW 용어 파악 - OS 발달 역사
## 컴퓨터의 기본 구성 요소
- 프로세서(또는 CPU): 프로그램을 실행하는 장치
- 메모리: 데이터와 프로그램(명령어 집합)을 저장하는 장치. 휘발성
- I/O 모듈: 컴퓨터와 사용자 사이에서 데이터를 이동시키는 장치
  - CPU, 메모리 제외 나머지가 여기에 해당(디스크, 그래픽카드 등)

이들은 **버스**라는 물리적 통로로 서로 연결되어 있음
## 프로그램의 실행 과정
### 프로그램과 프로세스의 차이
- 프로그램: 특정 작업을 수행하기 위한 명령어 집합
- 프로세스: 메모리에 적재된 프로그램. CPU에 의해 실행될 수 있는 상태
### 프로그램의 변화 과정
1. 소스 코드
   - 컴파일 결과 기계어로 변환
2. 기계어
   - 기계어와 명령을 1대1로 대응한 것 - 어셈블리어(아키텍처마다 다른 형태)
   - 기계어로 컴파일된 프로그램은 디스크에 저장
   > [참고] 리눅스 계열 OS: 컴파일된 프로그램을 .elf 포맷으로 저장
### 컴퓨터 부팅 과정
1. 컴퓨터 전원 들어옴
2. 디스크의 퍼스트 블록(리눅스 - 부트 블록)에서 로더 실행
3. 로더에 의해 메모리에 OS 적재
4. 이제 컴퓨터는 OS에 의해 관리되는 상태
### 프로그램 실행 과정
1. 프로그램 실행 트리거(GUI 기반 OS의 경우 아이콘을 클릭하는 행위)
2. OS가 메모리에 프로그램 적재(디스크에서 복사)
   - 즉 디스크에 있던 프로그램이 OS에 의해 메모리 내에서 프로세스가 되어 CPU에 의해 실행될 수 있음
3. CPU가 프로세스의 명령어를 하나하나씩 수행

## 프로세서(CPU)의 구성 요소 및 작동 과정
자세한 내용은 컴퓨터구조론 과목 통해 공부 추천
### 구성 요소
- ALU(Arithmetic/Logic Unit)
  - 산술 연산(사칙연산) 및 논리 연산(참거짓, 불 대수)을 수행하는 장치
- 레지스터
  - 프로세서 내에서 사용하는 저장 공간
  - PC(Program Counter): 다음에 수행할 명령어의 **주소**를 저장하는 레지스터
  - IR(Instruction Register): 현재 수행할 명령어를 저장하는 레지스터
### 작동 과정
프로세스가 한 명령어를 실행하는 과정을 **Instruction Cycle**이라고 함
1. fetch
   - fetch의 사전적 의미: 반입하다
   - PC가 가리키는 메모리 주소로부터 명령어를 IR에 적재
2. decode
   - IR에 저장된 명령어의 의미를 파악하기 위한 처리(해석) 단계
3. execute
    - 해석한 명령을 ALU를 통해 실행하는 단계
## 프로세서의 발달(진화) 과정
- **bandwidth**(메모리에 대한 데이터 I/O 처리량)이 증가하는 방향으로 발전 
  - 8비트 프로세서란? 메모리 주소도 8비트, 레지스터도 8비트(즉 한번에 처리할 수 있는 정보량이 증가)
- **clock speed**(단위시간당 명령어 실행횟수)가 높아지는 방향으로 발전
> 성능이 좋아지는 만큼 전력소모, 내부 설계 복잡도, 발열이 함께 증가하는 문제 발생
> - 교재 그림 보면 90년대에 절정임을 알 수 있음
- 위의 문제로 인해 2000년대 인텔, AMD 등의 회사에서 멀티코어 프로세서 출시
### 저성능 프로세서
- 예) 8비트 프로세서의 경우 TV 리모콘 등에 사용됨. 프로세서 판매 수량으로만 따지면 64비트보다 더 많음
- ARM 프로세서는 스마트폰 등에 사용됨
### 최근 프로세서 경향
옛날에는 하나의 종류로만 확장하는 방식으로 멀티코어를 정의했다면, 요즘은 멀티코어를 이루는 프로세서의 종류가 다양하게 구성
- [참고] 예시: 퀄컴 스냅드래곤 865, 삼성 엑시노스 990 등등
- **big-little solution**
  - 위 예시의 프로세서가 사용하는 아키텍처이며 ARM에서 제시한 솔루션
  - 하나의 빅 코어와 여러 개의 리틀 코어로 구성
  - 빅 코어(big core): 고성능 코어이며, 로드(계산량)-전력 그래프에서 초반에 전력소비량이 크지만 증가폭 기울기가 완만
  - 리틀 코어(little core): 저성능 코어, 로드-전력 그래프에서 초반에 전력소비량이 작지만 증가폭 기울기가 급함
- **dynamic frequency algorithm**(리눅스 진영에서 부르는 이름)
  - 데이터 로드량의 크기에 따라 사용할 코어를 구분하여 동적으로 명령 처리하는 알고리즘
  - 최신 논문에 따르면 해당 알고리즘을 사용할 때 전력 소비량이 30-40% 감소
> #### 분업의 시대 
> - CPU가 범용 목적에 이용되는 한편, GPU는 덧셈 뺄셈 등의 특정한 목적에 최적화됨
> - 인공지능에는 많은 양의 사칙연산이 활용되는데(가중치 계산 등), 이때 GPU를 활용하면 하나의 연산을 대량으로 수행할 수 있어 효율적임
>   - 더 나아가 AI에 최적화된 NPU까지 활용한다면 더 효율적일 것

### 폰 노이만 아키텍처
- 적절한 소프트웨어를 메모리에 올려놓기만 하면 프로세서가 그에 맞게 명령 수행하는 시스템
- 폰 노이만 아키텍처를 이용하면 소프트웨어의 목적에 따라 범용으로 시스템 사용 가능

> 알파고와 이세돌의 대국에서 알파고가 승률은 높았지만 전력소모가 엄청났음
> - 그 원인은 메모리에서 발생하는 병목현상인 **폰노이만 병목**
> - 폰 노이만 구조에서 데이터를 로드 및 처리하기 위해 메모리에 반복적으로 접근하기 때문
> - 인공지능에는 폰 노이만 아키텍처가 어울리지 않음

### 미래 - Neuromorphic Architecture
#### 폰 노이만 병목 해결 방법(제안)
1. 프로세서와 메모리 사이의 버스의 대역폭 확장
2. 프로세서의 구조를 단층이 아닌 복층 구조로 설계

> 1, 2번은 폰 노이만 병목의 본질적인 문제(아키텍처 설계상에서 문제)를 해결하지 못함

3. [중요] 인간의 신경망(뇌구조)을 하드웨어로 구현 - **Neuromorphic Architecture**
- 사람의 효율적인 예측 능력으로부터 힌트를 얻은 아키텍처 방식(패러다임)
- 전력소모 매우 감소(분산 컴퓨팅으로 인한 초저전력)
- 상용화 아직 안됐으나, 빠른 시일에 되지 않을까..?
