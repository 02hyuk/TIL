# 2. Computer System Overview II
## 메모리
### 메모리 고려사항
- 용량
- 속도
- 가성비
이 3가지를 모두 잡는 메모리 종류는 존재하지 않음

### 현대 메모리 분류
SRAM: 속도가 빠르지만 가격이 비싸며 작음
DRAM: 속도가 상대적으로 느리지만 가격이 저렴함
> 현대 컴퓨터의 메모리 시스템은 두 종류의 메모리를 함께 사용해 서로를 보완하는 방향으로 발전

### 메모리 계층
- 컴퓨터 시스템 내 메모리fmf CPU와 가까운 순서대로 배치한 피라미드 모형
- 피라미드의 위에서 아래로 내려갈수록..
  - 메모리 접근 시간이 증가
  - 용량 증가

> - 현대 컴퓨터 시스템에서는 최대한 하위 계층 메모리에 접근하는 횟수를 최소화해 접근 속도 향상
> - 이를 최소화하기 위해 알아야 하는 시스템의 특성이 **참조의 지역성**

### 참조의 지역성(locality of reference)
시스템이 메모리를 참조할 때 어느 정도 지역성을 보인다는 특성
1. 시간 측면(temporal locality): 어느 메모리 위치에 접근했을 때, 얼마 뒤에 다시 접근할 확률이 높음
- 루프문에 의해 특정 명령어가 반복적으로 실행될 때, 해당 명령어 위치에 계속 접근
2. 공간 측면(spatial locality): 메모리에 접근할 때, 최근에 한 번 접근했던 위치의 근방에 접근할 확률이 높다는 특성
- 배열 등의 아이템 접근시 순서대로 접근
- 메모리에 저장된 명령어도 순차적으로 실행됨

> 따라서 자주 접근하는 데이터를 상위 계층에 두고, 나머지를 하위 계층에 두는 것이 효율적

### 평균 접근 시간(Average Access Time)
- hit
  - 접근해야 하는 메모리의 데이터가 상위 계층 메모리에 존재하는 경우를 hit라고 함
  - H(hit rate, hit ratio): 데이터 접근시 hit될 확률
  - T1: 상위 계층에 접근할 때 걸리는 시간
  - T2: 하위 계층에 접근할 떄 걸리는 시간
- miss
  - 상위 계층에 없어 하위 메모리에 접근해야 하는 경우를 miss라고 함
  - 데이터에 접근할 때 miss가 될 가능성을 miss rate라고 하며 그 확률은
  - M = 1 - H
- 평균 접근 시간(Average Access Time)
  - T = H * T1 + (1 - H)(T1 + T2) = -T2 * H + (T1 + T2)
  - 평균접근시간 T는 hit rate H에 대한 일차함수 형태로 나타남
  - 상위 계층에서 먼저 찾고서 miss임을 확인한 뒤 하위 계층으로 이동하므로 소요 시간은 T1 + T2가 됨 

> - 실제로 메모리(DRAM) 액세스 타임은 캐시의 100배쯤이므로 히트율이 높지 않으면 굉장히 비효율적
> - 따라서 히트율을 조금이라도 올릴 수 있다면 평균 접근 시간을 유의미하게 줄일 수 있음

### miss rate와 평균 접근 시간
둘의 변화율이 비슷하므로, 상대적으로 성능 변화(평균접근시간) 분석에 유용함
- 당연하지만 비례관계 아님
> T2 = 100 * T1이라고 가정했을 때 hit rate와 miss rate의 수치 변화
> - hit rate를 97%에서 99%로 2% 올렸을 때 평균접근시간은 2배 감소
> - 그러나 hit rate의 변화율과 평균접근시간 변화율 크기의 차이에서 괴리 발생
> - 이때 miss rate는 3%에서 1%로 변화하는데, 그 변화율이 성능 변화율과 비슷함

## 캐시 구성
- 성능 향상을 위해 CPU와 메모리 사이에 캐시 존재 
- 현대 컴퓨터 - 여러 개의 캐시를 L1, L2, L3로 구분

### 캐시 도입 배경
프로세스를 실행할 때 메모리에 최소 1번은 접근해야 함
- 명령어 사이클에 의해 필연적으로 명령어를 IR에 fetch하므로
- 때로는 특정 명령어에 의해 특정 메모리에 값을 저장하므로

이러한 이유로 성능 향상을 위해서는 메모리 접근 횟수를 최소한으로 줄여야 했음
> 그렇다면, 아주 빈번하게 접근되는 데이터를 상위계층 메모리인 캐시에 적재하면 되지 않을까?

라는 생각에서 캐시 구조가 고안되었다고 함

### 캐시와 참조의 지역성
1. temporal locality → 한 번 접근한 메모리를 hot data로 간주하고 캐시에 적재
2. spatial locality → 한 번 접근한 메모리 근처의 메모리를 hot data로 간주하고 그 근처의 워드를 블록으로 묶어 캐시에 적재

#### 메모리, 캐시에서의 단위
- 워드(words): 32비트(32비트 컴퓨터 기준)
- 메모리: n비트 주소체계 → 2^n개의 방(워드) 존재(0 ~ (2^n) - 1)
  - 32비트 주소체계인 경우 2^32개(4 * 2^30 = 4 기가비트)의 워드가 존재
- 블록: 워드 K개 묶음
  - 메모리의 총 블록 수 M = (2^n) / K
  - 한편 캐시의 블록 수는 C로 표기
  - C << M(차이 매우 크단 뜻) - 비용 문제로 캐시를 메모리보다 작게 설계
- 라인(슬롯): 블록(데이터), valid 비트, 블록 구분용 태그로 구성된 캐시 내에서의 저장 단위
  - valid 비트: 캐시 안에 데이터가 있으면 1, 없으면 0을 저장하며 valid 비트와 태그를 통해 hit, miss 결정
- 태그: 각 라인에 존재하는 블록을 구분하기 위한 식별자
  - 예) 태그 = 메모리주소 / 8 (몫) -> 0, 24번 모두 대응되는 라인이 같지만 0번의 태그는 00, 24번의 태그는 11
- 집합(set): 캐시 내에서 라인을 몇 개 묶은 단위
- 매핑 함수: 각 집합(또는 라인) 및 태그를 정하기 위한 함수
  - 예) Direct Mapped 방식에서 라인 = 메모리주소 % 8 (나머지) -> 0, 8, 16, 24번 메모리는 캐시의 0번 집합에 위치

## 캐시 작동 원리
[가정]
- 메모리 - 블록에 포함되는 워드수 1개, 메모리 5비트(0~31) → M = 2^5/1 = 32
- 캐시 - 캐시 내의 라인은 8개(C = 8)

### Direct Mapped
- 메모리의 블록과 캐시의 라인을 일대일로 대응하는 방식
- 한 집합에 하나의 라인 존재(one line per set)
  - 어떤 데이터든 자신이 위치할 라인이 매핑함수에 의해 바로 매핑된다고 해서 direct mapped 방식이라고 부름

#### 접근 시나리오
- 각 메모리 블록의 주소: A = 01000, B = 10100, C = 00110, D = 01011, E = 01110
- ABCDEB 순서로 메모리 주소 접근
- 매핑 함수: 라인 = 주소 % 8, 태그 = 주소 / 8

1. A-D까지는 라인이 겹치지 않아 캐시에 바로 저장
- 예) D(주소: 01011) 접근 과정 설명
  1. D가 저장될 라인: 011(뒤에 3비트가 011 - 나눴을 때 나머지가 3)
  2. 011번 라인의 valid 비트가 0 이므로 miss 
  3. 011번 라인에 D값을 저장하므로 valid 비트: 1, 태그: 01로 수정(8로 나눈 몫 - 앞 2비트)
2. E에 접근할 때 캐시에는 C가 존재해 miss, 해당 라인에 E 저장
> ##### (시간적)참조의 지역성
> - 나중에 접근한 E를 사용할 확률이 C를 사용할 확률보다 더 높다고 판단
- 저장 과정
  1. E(주소: 01110)의 경우 대응되는 라인의 번호가 110 
  2. 캐시 내 해당 라인의 valid 비트가 1 
  3. 하지만, 라인의 태그가 00이므로 E의 태그 01이랑 불일치하므로 miss 
  4. 라인의 데이터를 E로 수정
3. B에 접근할 때 이미 캐시에 B가 존재하므로 hit
- 100번 라인의 valid 비트가 1이고 태그도 10으로 B와 동일하므로 B가 존재한다고 판단

### 2-way Set Associative(집합 연관)
- 라인 2개를 집합(set) 하나로 묶어 캐시에 저장하는 방식
  - 이를 일반화한 것이 n-Way Set Associative
- direct mapped 방식과 달리, 집합을 구분함
- 집합 내에서 라인을 구분하려면 태그 이용
- 캐시에 저장할 때 집합 전체를 탐색하므로 오버헤드 발생
  - 이를 해결하기 위해 병렬 처리 가능한 하드웨어를 도입할 수 있으나, 그 비용까지 생각해야 함
> #### 완전 연관
> - 캐시 전체를 하나의 집합으로 사용하는 방식(즉 E = C)
> - cache utilization 증가 
> - 빈 라인에 넣기만 하면 되므로 원소가 겹칠 일이 적어짐 
> - 하지만 그만큼 탐색시간 증가

[가정]
- 메모리와 캐시의 조건은 Direct Mapped 방식의 시나리오와 동일

#### 접근 시나리오
- 접근할 메모리의 주소와 접근 순서 모두 동일
- 매핑 함수: 집합 = 주소 % 4, 태그 = 주소 / 4
  - 2-way set associative 방식이므로 집합에 두 개의 워드 존재
  - 따라서 전체 라인 수에서 2를 나눈 수만큼 집합이 존재해야 함
  - 그 결과가 4개이므로 매핑 함수를 위와 같이 정의

1. A,B는 00번 집합에 차례로, C는 10번 집합의 처음 라인에 저장
2. D는 11번 집합의 처음 라인에 저장
> D가 저장될 11번 집합의 처음 라인부터 valid = 0 -> miss -> 처음 라인에 D 저장
3. E는 10번 집합의 두 번째 라인에 저장
> E는 10번 집합에 해당 -> 처음 라인에 C 저장됐으므로 miss -> 다음 라인 탐색 -> 없으므로 miss -> 여기에 E 저장
4. B에 다시 접근시 hit 발생
> B 다시 접근 -> 00번 집합 검사 -> 두번째 라인에 valid=1, 태그 일치 -> hit -> 캐시 접근

## 캐시 설계시 고려 사항
### 연관도
- 매핑 함수를 어떻게 설정하냐를 말함
  - 집합 내에 존재하는 라인의 수를 의미함
- 연관도에 따라 성능 달라짐
  - 연관도 상승시 좀 더 유연해짐
  - 하지만 캐시 탐색 시간 증가

### 블록의 크기
- 캐시를 이용할 때 공간적 지역성을 위해 블록 단위로 prefetch
- 어플리케이션에 따라 블록의 크기를 적절히 설정해야 성능 최적화 가능
- 블록 크기를 크게 한다고 무조건 좋은게 아님
  - 예 - 루프: 루프 종료시 다른 명령어를 실행하므로 멀리 있는 메모리에 접근할 가능성 발생(캐시 용량 낭비)

### 캐시의 용량
- 클수록 hit rate 증가
- 하지만 가격이 비싸므로 크기를 적절히 선택해야 함
- 캐시의 용량: S * E * B
  - S는 집합의 개수, E는 집합 내 라인의 수, B는 블록의 크기 의미

> #### [예시] 인텔 i7 프로세서의 캐시
> - L1이 32KB이며, CPU와 멀어질수록 용량이 커짐(L3 - MB 단위)
> - 인텔 i7의 L1 캐시의 용량은 32KB
>   - 왜냐면 캐시 전체 용량 = S(64개) * E(8개) * B(64바이트)
>   - 이를 계산하면 (2^6) * (2^3) * (2^6) = 2^15바이트 = 32KB
