# 2. OSI Reference Model
## 프로토콜 계층화
프로토콜에 명시된 규칙을 적절히 나누어 계층별로 배치한 것을 프로토콜 계층화(Protocol Layering)라고 함
> 각 계층에 규칙의 일부가 분배되었으므로 계층마다 프로토콜이 존재

### 등장 배경
1. 각 컴퓨터의 시스템 구성이 다른 방식으로 설계된 경우가 많아 
동일한 프로토콜을 사용해 통신하기 불편함 
2. 통신 과정에서 상호 시스템의 차이, 제약조건을 보완하는 중개자가 필요 
3. 이때 중개자는 모든 시스템에 대해 보편적인 방식으로 중개할 수 있어야 하는데, 
하나의 프로토콜로는 모든 시스템을 중개하기 어려워 계층화를 통해 담당 부분을 나눠 문제를 해결하고자 함

### 특징
- 프로토콜에 대한 계층 구조이므로 **Protocol stack**이라고도 함
- 현재 계층에서 데이터를 변환한 뒤 다음 계층으로 전달하는 방식으로 동작
- 각 계층은 자신의 책임만 다 하고 전달만 하면 끝이므로, 다른 계층을 고려할 필요 없음
- 우리가 이해하기에는 쉽지만, 계층화에 따른 추가 처리로 인해 전체 시스템의 복잡도 증가
> 시스템의 복잡도가 증가하더라도 계층화 방식을 선택한 이유
> - 실제 통신(소통) 과정이 대부분 순차적으로 이루어지기 때문에 이해하기 쉽고, 성능 측면에서도 꽤 괜찮은 방법
### 레이어의 구성 요소
**서비스**
- 현재 레이어가 수행하는 기능, 산출물을 말하며 상위 레이어가 현재 레이어에게 기대하는 것을 의미
  - 즉 상위 레이어에서 호출할 수 있는 함수 형태로도 이해 가능
  - 이 맥락에서 프로토콜은 서비스에 대한 내용을 어떻게 실행해야 하는지 *구현한 내용*에 가까움
- 특정 레이어에서 제공하는 서비스는 교체 가능함
- 예: 이더넷(Ethernet), IP, TCP 등
**인터페이스**
- 레이어 사이에서 정보를 교환하는 방식(즉 프로토콜)을 의미
- service interface: 상-하위 레이어 간 메시지 교환 규약. 실제로 수행할 수 있는 명령의 형태
- peer interface: 동일 레이어 간(수평 관계에서 서로) 메시지 교환 규약
> 동일 레이어 사이의 구조와는 상관 없이, 둘 사이에서 의사소통이 되어야 함
### 프로토콜 그래프
- 상-하위 레이어 간 메시지 전송 관계가 형성하는 그래프 
- 계층에서 이용하는 서비스를 노드에 표시 
- 호스트 간 통신시 각 계층에서 어느 서비스를(프로토콜을) 사용해 데이터가 전달되는지 파악 가능

### 캡슐화/역캡슐화
정보 송수신시 데이터 흐름을 보면,
1. 정보를 송신할 때
  - 한 노드 안에서 데이터 패킷은 상위 계층에서 하위 계층으 이동
  - **캡슐화**(encapsulation): 패킷을 수신할 동일 계층이 패킷을 적절히 처리할 수 있도록 하는 메타데이터 추가
  - 상대방에게 송신할 데이터의 앞에 붙이는 메타데이터를 **헤더**(일반적), 뒤에 붙이는 메타데이터를 **트레일러**라고 함
2. 정보를 수신할 때
  - 송신 과정과 반대로 하위 계층에서 상위 계층으로 데이터 패킷 이동
  - **역캡슐화**(decapsulation): 현재 계층에 도착한 패킷에 붙은 메타데이터를 분리해 적절한 처리를 하는 것
> 각 레이어에 도착한 데이터는 다른 레이어들의 헤더가 붙은 상태이겠지만, 신경쓰지 않고 원래 데이터 내용이었던 것처럼 송수신 처리함

## OSI 참조 모델
- 국제 표준화 기구(ISO)에 의해 진행된 컴퓨터 네트워크 프로토콜 집합(suite) 프로젝트
- 현재 시점에서는 인터넷에 밀려 실패했으나, 네트워크를 이해하기 위한 틀로서 공부할 가치가 있음
- 최하위 1계층부터 최상위 7계층까지 총 7개 레이어 존재

### Layer 1 - 물리 계층(Physical Layer)
- 데이터를 포함한 전기 신호를 전달하기 위해 필요한 계층
- 실제 전기 신호와 비트 정보(비트열) 사이의 변환을 담당
- 두 노드 간 연결이 어떤 케이블/링크를 사용하는지, 전기 신호를 어떻게 전달하는지가 주요 토픽

### Layer 2 - 데이터 링크 계층(Data Link Layer)
- 링크를 통해 연결된 두 노드 사이에서 정보를 전달하는 역할
  - 두 노드 외의 영역에는 신경쓰지 않음
  - [참고] hop-to-hop delivery: 한 호스트에서 다른 호스트로 정보를 전달할 때 그 사이에 존재하는 노드를 거쳐 데이터 링크 계층을 통해 데이터가 전달되는 것
- 비트열과 프레임 사이의 변환을 담당
> 프레임화(Framing)
> - 프레임의 형태로 데이터의 시작과 끝부분을 정의하는 것 
> - 데이터의 시작과 끝을 명시하지 않으면 현재 노드에서 수신 중인 데이터가 0인지 1인지 구분하기 어려움
- 여러 노드가 연결된 경우 목적지를 구분하여 데이터를 전달하는데 필요한 계층
  - 원한다면 모든 노드에 데이터를 전달할 수 있음
- 해당 계층에서 사용되는 프로토콜
  - MAC Address, Ethernet, 802.11(WiFi)

### Layer 3 - 네트워크 계층(Network Layer)
- 노드와 링크 집합, 즉 한 네트워크 전체를 고려해 데이터 전송 경로를 최적화
- 데이터링크 계층에서 사용하는 프로토콜의 종류와 상관 없이 데이터를 동일한 방법으로 전달
  - 링크의 종류에 따라 전달 가능한 데이터 패킷의 크기가 다름
  - 이를 처리하기 위해 송신시 데이터를 분할하고(fragmentation, segmentation), 수신시 분할된 데이터를 다시 합치는(reassemble) 작업 수행
- 필요한 경우 수신한 데이터 패킷을 큐에 보관하기도 함(queueing)

### Layer 4 - 전송 계층(Transport Layer)
- 프로세스 간 데이터 교환에 필요한 계층
  - 어느 프로세스에서 데이터를 보냈고, 어느 프로세스가 데이터를 받아야 하는지를 관리하는 역할
- 프로토콜 예: TCP
  - 종단 간(프로그램 사이) 가상의 연결을 만드는 특징 존재

### Layer 5 - 세션 계층(Session Layer)
- 세션을 생성, 관리, 종료하는 역할의 계층
  - 세션: 애플리케이션 사용시 유지해야 하는 정보이며 사용 종료시 제거 (예: 웹사이트 로그인 정보, 장바구니 등)
> - OSI 참조 모델을 고안할 당시에는 프로토콜로서 세션을 관리해야 한다고 생각하고 계층을 정의함
> - 그러나 현재 세션은 주로 애플리케이션(웹개발) 영역에서 다루는 기술이 됨

### Layer 6 - 표현 계층(Representation Layer)
- 정보 변환(압축 등), 암/복호화에 필요한 계층
- 서로 다른 시스템이라도 동일한 방식으로 데이터를 해석하는 데 필요한 계층
  - 각 시스템에서 사용하는 데이터 포맷이 다르므로 수신 정보를 의도와 다른 포맷으로 해석할 수 있음
- RFC 7531
  - 인터넷을 이용한 통신 과정에서 사용해야 하는 데이터 포맷을 정의한 문서
  - 각 데이터 형식명과 그 값을 맵핑한 C언어 코드로 이루어져 있음

### Layer 7 - 애플리케이션 계층(Application Layer)
- 응용 프로그램이 네트워크를 통해 정보를 송수신할 때 사용
