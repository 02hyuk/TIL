# 1. Overview of Computer Networks
## 네트워크
- 점들의 집합이 선으로 연결되어 있는 것
  - 인물관계도, 지하철 노선도 또한 네트워크라고 볼 수 있음
  - 복잡한 시스템의 본질을 이해하기 위해 그래프를 사용하여 표현한 것이 네트워크
  - 점과 점 사이에 선을 통해 무언가가 교환되는 것

### 컴퓨터 네트워크
1. 단일 기술을 통해 자율적으로 동작하는 컴퓨터(pc, 태블릿 등)가 상호 연결되어 있는 집합
   - 컴퓨터를 상호 연결한 기술이 다르면 안 됨
     - 연결 기술이 이더넷인 기기와 와이파이인 기기가 서로 연결되어 있다고 하더라도 하나의 네트워크라고 말하지 않음
     - 서로 연결되어 통신이 되는 것은, 서로 다른 네트워크를 연결하는 기술 덕분
   - 컴퓨터 간 계층 관계(지시 - 수동적 관계)가 있으면 안 됨
2. 각 컴퓨터가 통신 채널을 통해 상호 연결되어 서로 정보 교환이 가능한 상태의 컴퓨터 집합
   - 링크와 채널은 다른 개념.
   - [참고] 불특정 다수의 컴퓨터(관심 없는)가 모인 네트워크 집합을 클라우드라고 함
#### 교통망과 컴퓨터 네트워크 비교
- 차량/사람 ~ 패킷(데이터에 대한 정보까지 합한 것)/페이로드(데이터)
- 주소 ~ IP 주소
- 교차로 ~ 브릿지, 라우터
- 도로 ~ 링크, 패스
비슷한 점들이 꽤 많음

### 컴퓨터 네트워크 구성 요소
- 노드(nodes): 특정 목적의 장치
  - PC, 서버, 스위치, 브릿지, 라우터
- 링크(links): 노드 사이를 물리적으로 연결하는 것
  - 광섬유(optical fiber), 동축 케이블(coaxial cable), 무선연결 등
  - 하나의 링크에 여러 채널(노드 사이를 논리적으로 연결하는 느낌)이 대응

## 인터넷(Internet)
- 상호 연결된 네트워크로 이루어진 시스템
- 네트워크의 네트워크
- 특정 기관에서 구축한 것이기에 고유명사 취급(대문자 I 사용)
> #### 인트라넷(intranet, private networks)
> - 모두에게 공개된 인터넷과 달리, 특정 인원들만 접속 가능한 네트워크

### 서비스 관점으로 바라본 인터넷
1. 통신 인프라를 제공하는 서비스
   - 통신 인프라를 통해 분산 서비스 이용 가능
2. 통신 서비스를 통해 데이터를 상호 교환할 수 있음
   - 데이터 교환 과정을 대신 처리해주는 용역
   - [주의] (전송 역할에만)best effort service: 데이터 전송에 대해서는 최선을 다하지만, 책임 외의 영역(장비 오류 등)에서 문제가 생길 경우 전송 실패
     - 일반우편 느낌(우체통에 편지가 없을 수 있음. 전송 성공을 보장하려면 등기우편 사용해야 함) 
3. 응용(분산) 프로그램 상에서 접근 가능한 인터페이스 제공
   - 소켓 프로그래밍이 이런 내용을 다루고 있음

### Internet Jargons(인터넷 용어)
- 호스트(hosts, end systems): pc, 폰, 태블릿 등
  - network edge라고도 함
- 통신 링크(communication links): 네트워크에서 노드를 연결하는 기술
  - 광케이블, 구리, 전파, 위성통신 등
  - 전송 속도, 자료 전송율(transmission rate, data rate): 데이터 전송량 / 시간
> 대역폭(bandwidth)은 전송속도와 비례하는 경향(Shannon-Hartley 이론)<br>
> → 대역폭도 속도의 의미로 사용
> - 대역폭: 신호가 차지하는 주파수의 범위
- 패킷 스위치(packet switches): 엔드 시스템에 해당하지 않는 장치들
  - 라우터, 스위치 등
  - 엔드 시스템으로 패킷(데이터 전송 단위. data에 대한 chunk라고도 함) 전송시 중개하는 역할
- 네트워크: 특정 집단(기관)이 특정 기술을 이용해 장치를 연결한 집합
- ISP(Internet Service Provider)
  - 서로 다른 네트워크를 연결할 때 중개하는 기관
  - 서로 다른 네트워크, ISP를 연결함
- CPN(Content Provider Network)
  - 컨텐츠 제공자가 서비스 사용자의 요청에 빠르게 응답하기 위해 구축한 네트워크
  - 구글의 사례가 그 예시

### 인터넷의 구조
- 네트워크 엣지(Network Edge)
  - 네트워크의 말단 부분으로서 호스트, 엔드시스템을 의미
- 액세스 네트워크(Access Networks)
  - 특정 엣지가 인터넷을 사용할 때 *처음으로* 접속하는 네트워크를 **액세스 네트워크**라고 함
  - 와이파이, 이더넷, LTE/5G 등 여러 통신 링크 중 하나로 연결
  - 액세스 네트워크 안에 있는 라우터를 edge router라고 함
- 네트워크 코어(Network Core)
  - 서로 다른 네트워크를 연결하는 네트워크(network of network)
  - 수많은 **라우터**들이 그물처럼 얽혀 있는 구조
  - packet switching : 네트워크 코어에서 패킷을 교환하는 것

## 인터넷의 역사
### 1960년대 - 70년대 초
1. 클라인락(Kleinrock)의 증명: 패킷 스위칭 방식의 효율성
2. 군용으로 패킷 스위칭 사용
   - 군대라는 집단 특성상 네트워크 장비 파괴 가능성이 높아 대비책이 필요했음
3. 알파넷(ARPAnet) 출범
   - 미 국방성 주도로 진행되던 패킷 스위칭 연구 프로젝트
   - 1969년 통신 최초 실행
4. (1972년)알파넷 민간 공개 후 15개 민간 노드 최초 연결
### 1970년대
1. ALOHAnet 개발
   - 하와이 대학에서 개발한 위성 통신 기술
2. Cerf와 Kahn이 **네트워크 간 상호 연결 구조**를 고안
   - **패킷 스위칭** 기술을 위의 구조에 사용
   - 아래의 특징을 갖도록 상호 연결 이론 제안
     - 복잡하지 않게
     - 네트워크 서비스 운영자의 자율성 보장
     - best effort: 최고급 서비스보다는 기본 역할에 충실
     - 라우터나 스위치의 무상태성(stateless)
     - 네트워크의 특정 엣지에 권력 집중되지 않도록(decentralized control)
   - 인터넷의 기반 원리가 됨
3. Xerox PARC에서 **이더넷** 기술 개발
### 1980년대
1. 위의 Cerf와 Kahn을 포함한 연구자들이 **TCP/IP** 프로토콜 개발
2. 다양한 프로토콜 개발
   - smtp: 이메일 프로토콜
   - dns: 도메인 서비스 프로토콜
   - ftp: 파일 전송 프로토콜
3. TCP/IP 프로토콜에 혼잡 제어 기능 추가
### 1990년대
1. 미국 정부가 알파넷을 **인터넷**이라는 새 이름으로 **민간 공개**
2. 인터넷을 이용한 다양한 산업 증가 (ex:아마존)
3. 닷컴 버블

### 새천년 ~ 최근
1. 인터넷 기술 발전
2. 새로운 네트워크 기술 발명
   - SDN, 4G/5G, WiFi 등
3. 대형 IT 기업(구글, 마이크로소프트 등)이 자신의 네트워크 구축
   - 자사의 데이터센터에 수십 만 대의 컴퓨터를 구축해 컨텐츠를 원활하게 제공
   - 유휴 자원이 발생할 때 사용자에게 유료로 대여하는 **클라우드** 서비스 탄생
4. 2023년 기준 인터넷의 호스트는 대략 150억 대

### 오늘날의 인터넷
- 민간에서 운영하는 인프라 시스템이지만 공공재 성격을 띠므로 주도기관은 NGO(비정부기구) 형태로 운영됨
- 호스트는 ISP에 접속해야만 인터넷에 연결됨 - 액세스 ISP
- 그리고 모든 ISP가 서로 연결되어야 전세계의 컴퓨터가 정보 교환 가능

### ISP 연결 형태의 역사
1. 모든 액세스 ISP를 각각 연결할 때(complete graph의 형태로 연결) 링크의 수는 O(N^2)를 따르므로 비효율적
> - ISP가 하나 추가될 때마다 이전에 있던 ISP가 새 ISP에 모두 연결되어야 함
> - N개의 ISP를 연결하는 링크의 수 C(N) = C(N - 1) + N - 1
> - 기본적으로 C(2) = 1이므로 C(N) = 1 + 2 + ... + N - 1 = N(N - 1)/2이므로 C(N) 은 O(N^2)를 따름
2. Global ISP를 통해 각 액세스 ISP를 연결하는 방법 고안
   - 하나의 ISP가 전세계의 백만 단위의 ISP를 연결해야 하므로 그 규모가 매우 커야 함
   - 장비 하나로 부족하기에 글로벌 ISP 내부에 여러 장비를 복잡하게 연결하여 구축 -> 비용
3. 여러 회사에서 글로벌 ISP 구축
- 글로벌 ISP 방식 채택시 비용이 커 경제적 측면을 생각해야 함
- 액세스 ISP: 소비자/ 글로벌 ISP: 생산자의 형태로 계약
- 글로벌 ISP 간 경쟁 발생
4. IXP(Internet Exchange Point)
   - 글로벌 ISP 간 연결이 쉽지 않아 이를 중개하는 역할의 IXP 등장
5. Peering Link
   - 규모가 큰 글로벌 ISP 간 직결하는 링크
   - IXP를 사용할 때 전송 용량 제한 문제로 직접 링크를 구축하게 됨
     - 비용은 IXP를 이용한 경우가 저렴할 수 있음
6. Regional ISP
- 소규모 지역 내에서 액세스 ISP를 연결해 글로벌 ISP와 중개하는 역할
- 글로벌 ISP의 영향력 견제 목적의 액세스 ISP 연합이라고 보면 될 듯
7. CPN(Content Provider Network)
- 구글, 유튜브 등의 컨텐츠 회사가 대용량의 컨텐츠를 보낼 때 문제 발생
  1. 대역폭 문제로 인한 병목 현상 
  2. 비용 문제
- 따라서 컨텐츠 회사가 위의 문제를 해결하고자 직접 구축한 네트워크를 CPN이라고 함
> 용어 추가
> - Tier 1 ISP(Network) = 국가 단위, 국제 사이즈로 동작
> - Tier 2,3(?) ISP = Regional ISP
> - 최하층: Local ISP = Access ISP

## 프로토콜
- 사전적 의미: 의전(외교 상황에서 양국 간 지켜야 하는 예의, 규범)
- 컴퓨터 네트워크 분야: 통신시 지켜야 하는 규칙
  - 정해진 규칙을 따르며 통신해야 하므로 사실상 통신 프로그램이라 봐도 문제 없음
### 프로토콜의 조건(3요소)
1. 문법(Syntax)
- 서로가 수용 가능한 포맷으로 메시지(비트열 형태)를 주고 받아야 함
- 필드의 구조를 정의
> 필드(fields): 메시지 내 영역을 구분한 것
> - 헤더: 앞부분의 필드로 데이터 전달에 필요한 메타데이터
> - 페이로드: 전달하고자 하는 데이터(내용물)

2. 의미(Semantics)
- 메시지의 의미를 부여하는 규칙이 있어야 함
- 구분된 필드로부터 의미를 파악(decode)하
- 예시(실제 X): 헤더 비트열이 001이면 요청 메시지를 의미
3. 타이밍
- 어느 타이밍에 어떤 메시지를 보내야 하는가를 규칙화한 것

## 표준
널리 통용되는 행동, 작업 방식
> 등장 배경
> 1. 각 기업, 조직마다 프로토콜을 정의해 통신 
> 2. 타 조직과 통신하기가 어려워 통일 필요성 체감

- [참고] 특히 네트워크 분야는 표준을 지켰을 때 파급효과가 큰 편

### 표준화 기관
- SDO(Standard Development Organization)라고 하며 전세계에 널리 분포
- 종류(더 많음)
  - ISO: 국제 표준화 기관
  - ANSI: C언어 표준화한 곳
  - IETF: 인터넷 관련 기술 표준화 기관
  - W3C: 웹 분야(인터넷이랑 구분됨) 기술 표준화하는 기관
- De facto standards(사실상 표준)
  - 널리 사용되는 기술이지만, 국제적으로 공인받지 못한 것들
  - 예: 초기 pdf(현재는 표준화됨)
### 규제 기관(Regulatory Agencies)
법과 표준을 확인하여 규제하는 기관
- 한국은 방송통신위원회가 그 역할을 함
  - 국내에서 생산된, 국내로 수입된 휴대전화는 방통위에서 인증받은 뒤 소비됨
  - 그래서 휴대전화에 KCC마크(방통위 인증 의미) 붙어있음
### 인터넷 표준
IETF라는 기관에 의해 기술 표준화되며, 해당 기관에서 문서를 아래의 기준으로 분류
- draft standard: 아직 개발 중이라 드래프트(초안)만 작성된 문서
  - 해당 단계에서 추천을 많이 받아 채택된 초안은 RFC(Request for Comment)로 분류되어 번호 부여
- proposed standard: 특정 집단에서 표준으로 제안한 비공식 문서(기술)
  - 해당 단계에서 표준에 관한 테스트가 이루어짐
- Internet standard: 인터넷 사용자가 지켜야 하는 표준을 명시한 문서(기술)
  - 테스트가 충분히 이루어져 괜찮다고 검증받은 단계
