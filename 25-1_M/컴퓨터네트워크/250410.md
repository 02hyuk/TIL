# 과제 중에 알게 된 것들
## 리눅스 쉘

- 커널(핵심)을 감싸고 있는 껍질 → 사용자와 커널 사이를 잇는 프로그램
- (윈도우 WSL 환경에서) 터미널을 여러 개 켜두면 **각각 다른 프로세스로 인식**
    - 각 터미널 창에서 클라이언트, 서버 프로그램을 따로 수행하면 TCP 통신이 됨.. 경험담

### **터미널**

쉘을 이용해 입력과 출력을 얻는 **화면 자체.**  이게 진짜 인터페이스 같은데

쉘을 잇는 거니까 얘를 쉘이라고 생각해도 무방하지 않을까?

### 쉘에서 명령어 실행하는 방식

1. 명령어 입력 → 파싱
2. 자식 프로세스 생성
    - 내부적으로 `fork()` (복제) - `exec()` (용도 변경) 실행
3. 자식 프로세스가 명령 실행
4. 명령 끝날 때까지 쉘 대기
    - 백그라운드 옵션 설정시 명령 수행 중에도 쉘 수행 가능
5. 종료 후 쉘 기능 재개

## 소켓 프로그래밍 / C

쉘 명령어에 사용된 문자열 획득하는 법

- `int argc`: 명령 행으로 전달된 각 문자열(공백 기준 분리)의 수
- `char *argv[]`: 명령 행으로 전달된 각 문자열을 원소로 갖는 배열

`atoi()`  - 문자열을 숫자로 바꾼 뒤 반환하는 함수

소켓에 사용되는 주소 정보인 `sockaddr_in` 타입 변수를 `memset()`으로 초기화하는 이유

- 패딩(구조체 내에서 바이트 수를 맞추기 위해 빈 공간이 생기는 것)을 명시적으로 하는 용도로 정의한 필드 `char* sin_zero` 의 값이 쓰레기 값이면 네트워크 함수 호출시 문제 생길 수 있다고 함
- 즉 안전성, 동작의 예측 가능성 측면에서 `memset()`을 꼭 해줘야 함

연산자 우선 순위… **대입 연산자 < 비교 연산자** - 실수하지 말자

## 빅 엔디안 vs 리틀 엔디안

### 빅 엔디안

- 낮은 자리 수를 높은 메모리 번지에 저장하는 방식
- 네트워크 통해 데이터 전송하는 데 사용
- inet.h 헤더 파일의 `in_addr_t inet_addr(char* str)`은 str의 값을 빅 엔디안 숫자 형태로 리턴

### 리틀 엔디안

- 낮은 자리 수를 낮은 메모리 번지에 저장하는 방식
    - 우리가 보기에도 자연스럽고, 컴퓨터 입장에서도 연산할 때 편리
- 대부분의 시스템 내에서(예: 인텔) 데이터를 저장, 연산하는 데 사용
