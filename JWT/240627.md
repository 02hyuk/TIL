# JWT 안전하게 사용하는 방법 메모
## #1 JWT 사용시 액세스 토큰, 리프레시 토큰(갱신 토큰) 사용
- 사용자 인증(로그인 등) 후->액세스(수명 짧음), 갱신(수명 김) 발급
- 액세스 토큰이 도난당해도 수명이 짧기 때문에 영구적으로 사용 불가
  - 이로 인한 보안성 증가
- 액세스 토큰을 자주 갱신하면서도 사용자 인증은 하지 않아도 되기 때문에 일반적으로 많이 사용되는 방법
- 하지만 갱신 토큰이 탈취당하면 갱신 토큰의 수명만큼 위험에 노출된다는 단점 존재
## #2 액세스 토큰이 만료된 경우
갱신 토큰과 함께 서버에 새 액세스 토큰 요청
## #3 액세스 토큰 갱신시
이전의 갱신 토큰을 무효화한 뒤, 새로운 갱신 토큰 발급
## #4 갱신 토큰 도난에 대응하려면
세션 사용
- 갱신 토큰을 세션 아이디처럼 사용
  - 즉 갱신 토큰을 세션에 저장
- 세션에 저장된 사용자의 이전 접속 디바이스 정보, IP, Origin, 단위 시간당 접속 횟수 등을 검사 가능 
- 비정상적인 접근을 감지한 경우 세션을 삭제해 갱신 토큰 무효화
- 갱신 토큰을 세션ID처럼 사용시 JWT 대신 불투명 토큰(임의의 문자열)을 쓰는게 나음
  - 불필요한 정보 노출 방지
  - 요청 크기 절약
## #5 토큰(액세스, 갱신 모두)을 쿠키로 저장하고 아래 내용 적용
- 토큰이 도난당하는 것을 사전에 방지하기 위해 토큰을 쿠키로 저장
- 중간자 공격(토큰 탈취해 내용 엿보기) 대응 방법
  - SSL 인증서(HTTPS)로 암호화
  - 쿠키 설정시 Secure 속성 사용
- XSS(크로스 사이트 스크립팅) 대응 방법
  - HttpOnly 속성 사용
- CSRF(공격자가 의도한 행위를 통해 특정 웹사이트에 요청시킴) 대응 방법
  - SameSite 속성 사용
    - 웹브라우저가 쿠키를 받은 서버가 아닌 다른 서버로 요청하는 경우 쿠키 전송 못하게 함
